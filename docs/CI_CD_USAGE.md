# APIGuardX CI/CD Integration

APIGuardX can be called from a pipeline with a project-scoped CI/CD token. Tokens are generated by an authenticated user, shown once, stored only as a bcrypt hash, and scoped to one authorized API project.

## Create A Token

Log in with a normal user account and create a token for a project you own:

```bash
curl -sS -X POST "$APIGUARDX_API_URL/ci/tokens" \
  -H "Authorization: Bearer $APIGUARDX_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": 1,
    "name": "GitHub Actions",
    "expires_at": "2026-12-31T23:59:59Z"
  }'
```

The response includes `token` once. Store it immediately in your CI/CD secret manager as `APIGUARDX_CI_TOKEN`. Later list responses only return metadata such as `token_prefix`, `is_active`, and `last_used_at`.

## Trigger A Pipeline Scan

Use the CI/CD token with the `X-APIGUARDX-TOKEN` header:

```bash
curl -sS -X POST "$APIGUARDX_API_URL/ci/scan" \
  -H "X-APIGUARDX-TOKEN: $APIGUARDX_CI_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"threshold": 70}' \
  -o apiguardx-scan-result.json
```

You can also send the token as `Authorization: Bearer <token>`.

Optional request fields:

- `threshold`: integer from `0` to `100`. The API returns HTTP `422` when the scan risk score is greater than this value.
- `endpoint_ids`: list of endpoint IDs for a project-scoped subset scan. IDs outside the token's project are rejected.

## JSON Output

Successful and threshold-failed scans both return machine-readable JSON:

```json
{
  "scan_id": 42,
  "project_id": 1,
  "project_name": "Billing API",
  "status": "completed",
  "risk_score": 81,
  "risk_grade": "F",
  "threshold": 70,
  "passed": false,
  "should_fail_pipeline": true,
  "severity_counts": {
    "Critical": 1,
    "High": 2,
    "Medium": 3,
    "Low": 4
  },
  "findings": [],
  "completed_at": "2026-07-05T12:00:00Z"
}
```

## GitHub Actions

Add these repository secrets:

- `APIGUARDX_API_URL`: base URL of the FastAPI backend, for example `https://apiguardx.example.com`.
- `APIGUARDX_CI_TOKEN`: the one-time CI token generated from `/ci/tokens`.

Use `.github/workflows/apiguardx-ci-scan.yml` as the reference workflow. It posts to `/ci/scan`, saves the JSON result as an artifact, and fails the job when APIGuardX returns a non-2xx response, including when the risk score exceeds the threshold.

## Token Operations

List tokens:

```bash
curl -sS "$APIGUARDX_API_URL/ci/tokens?project_id=1" \
  -H "Authorization: Bearer $APIGUARDX_JWT"
```

Revoke a token:

```bash
curl -sS -X POST "$APIGUARDX_API_URL/ci/tokens/12/revoke" \
  -H "Authorization: Bearer $APIGUARDX_JWT"
```

## Security Notes

Only generate CI/CD tokens for APIs your team owns or has written authorization to test. Rotate tokens regularly, set expiration dates for shared environments, store tokens only in secret managers, and revoke tokens immediately when a pipeline or repository is retired.
